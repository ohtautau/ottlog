# 提示窗口规范（C257）

2026-10-11确认，适用于小程序。实现及验收见[开发说明](development.md#提示窗口统一规范c257)，正式决定见[决策记录](decisions.md#提示窗口统一规范c257)。

| 场景 | 组件与操作 |
| --- | --- |
| 普通确认／需要用户阅读的信息 | AppDialog或requestAppConfirmation，底部一个确认按钮 |
| 删除／移除确认 | 同一AppDialog，显式danger，显示实际对象和影响，沿原删除与重试流程 |
| 有修改时关闭编辑窗口 | useEditorCloseGuard中的AppDialog，左不保存、右保存；×继续编辑 |
| 无需决定的短反馈 | showAppMessage，非阻断，默认2400ms，后来的反馈替换前一条 |

创建、编辑、阅读、筛选及选择窗口继续使用对应共享组件。微信显式授权／订阅沿平台流程；应用提示不调用showModal、showToast或showActionSheet。不增加已有操作的确认步骤，不重复普通保存／创建／删除／结束成功提示；错误、校验、授权、未保存与数据保留等必要反馈保持。

## 外观与布局

| 项目 | 统一值 |
| --- | --- |
| 位置与大小 | 可用视口居中，宽度不超过360px，四周至少12px；短内容自然撑高 |
| 表面 | #22313d底色、#46605f的1px边框、12px圆角、共享阴影 |
| 遮罩 | rgba(4,10,16,.7)，覆盖应用可用视口 |
| 标题 | EditorHeading的prompt变体，18px／600／1.4；上8px、左右16px、下4px |
| 关闭 | 标题右侧×，40×40px触控，有具体无障碍名称 |
| 正文 | 14px／1.65、#dce6df，上下8px／左右16px；保留内部换行，去除尾部空白 |
| 长内容 | 原生ScrollView只滚动正文与错误区，标题、关闭和底栏固定，不截断文字 |
| 错误 | 正文下方8px，#efb7a2，role=alert，保持具体错误与重试信息 |
| 操作 | ActionButton的large／fill，48px高；两按钮等宽、间距8px，左右16px、上8px、下8px，无上边线 |
| 意图 | 普通主操作使用primary绿色；危险操作用danger；不保存为普通secondary |

浮动居中提示不额外累加底部安全区。主题由app-dialog.css拥有，页面不设置提示标题字号、背景、圆角、按钮尺寸或错误颜色。短反馈沿同一表面／文字／圆角，正文14px／1.65，无遮罩、无按钮且不接收触摸；长时间阅读的信息使用确认窗口。

## 行为与文案

- 标题说明当前操作，例如「删除习惯？」；正文说明实际对象及数据影响，按钮使用「删除」「保存」等实际动作。保留真实内容，不添加鼓励语或重复状态。
- ×、遮罩和Escape调用同一关闭入口，关闭结果为未确认，不触发删除或保存。多层窗口只关闭最上层提示。
- busy时关闭与操作沿原禁用规则；pending目标沿原业务守卫，不突破已有锁定或重试要求。由业务宿主持有的删除确认通过共享error区域保留错误和原目标，沿原ID重试，持久化成功后关闭。requestAppConfirmation只收集用户决定，确认后沿原业务保存器执行，失败回原业务界面或必要反馈，不为视觉统一重写业务流程。
- requestAppConfirmation按可见页面排队；页面隐藏／卸载取消该页未完成确认并清理反馈。账号／对象变更沿原宿主守卫，不把旧请求带到新账号。
- 普通确认不另加取消按钮；未保存提示保留不保存／保存，×表示继续编辑。未保存时保存失败返回原表单并保留输入。
- 应用确认显式传intent='danger'，不由按钮文案或任意confirmColor决定主题；兼容参数不改变统一样式。直接组合AppDialog的业务按钮同样声明appearance='danger'。

## 接入范围

共享普通确认、未保存提示，以及任务、习惯（两个宿主）、便签、领域、计时记录删除确认。格言、餐单记录、餐厅移除等已有requestAppConfirmation沿同一主题。表单与存档格式不变，不新增业务数据或修改默认样本。
