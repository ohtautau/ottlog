# Ottlog 设计指南 v1（建议基线）

这份指南用于约束之后的小程序和网页修改。它不是已完成全站重构的声明；现有页面按功能逐步迁移，用户明确提出的需求优先于默认规则。

2026-10-05 补充：小程序按 C18 将既有分析、图表与汇总集中到独立「统计」功能；下表原有“下滑分析”“今天的投入”“今日概览”等分析展示位置由此替代。原页面保留操作、当前状态与历史编辑，具体范围见 [统计说明](statistics-miniprogram.md)；网页现有分析布局保持其原有范围。

2026-10-05 C28 补充：小程序实体创建／编辑采用 [统一表单规范](../Design.md#实体创建与编辑c28)，以单按钮悬浮单选、常用标签行及末端多选浮窗、常用优先与末尾自定义输入为共用交互。备注在标题下常显；日程在标题上、图标在标题左、优先度在标题最右，空日程仅显示「日期」。所有展开／收起使用上下 chevron，打开顺时针旋转 180°、关闭逆时针旋转 180°。此决定替代下文旧的加减号展开与备注折叠建议，规范确认不表示全部页面已迁移。

## 1. 产品范式

采用 **核心任务优先、逐步展开、组件复用、主题有限变化** 的交互方式。

- 进入页面，用户应立即知道“我现在可以做什么”。优先显示任务对象及主要操作。
- 日常记录、分析和设置放到明确的次级区域；创建、编辑使用统一表单。
- 主题通过强调色、图形和少量文案表现，基础布局、控件语义和导航位置保持一致。
- 适合的工具页面采用两段式：第一页是一个可用视口高度的核心页，上滑对齐第二页起点；第二页按内容自然增长。首页按 C20 使用快捷入口、领域进展、全部入口三段；领域列表及详情采用页面导航，不强制套两段式。
- 核心页空间不足时减少装饰、减少首屏项目，将更多内容放入第二页；不得裁掉操作、无限缩小文字和触控区域。创建和编辑弹层保留独立的表单滚动。
- 前往下一段使用方向箭头；页内返回统一使用左箭头＋「返回」按钮。使用无障碍标签描述目的地，不显示“上滑 / 下滑”文字；展开／收起使用 C28 的旋转上下 chevron。拖拽、横向手势及四象限内部滚动不触发翻页。
- 页内顺序、空间关系应稳定。随机推荐只在进入页面或主动换一组时改变，不在用户触摸过程中跳动。

## 2. 固定四类页面模板

| 模板 | 用途 | 布局顺序 |
| --- | --- | --- |
| 操作工作区 | 番茄钟、任务四象限 | 状态/快捷控制 → 核心操作区 → 简要反馈 → 下滑分析/记录/设置 |
| 推荐与浏览 | 首页、习惯、文章列表 | 简短概览 → 分组卡片或列表 → 更多项目/管理 |
| 创建与编辑 | 任务、习惯、记录 | 标题与关闭 → 日程入口 → 图标／名称／优先度行 → 常显备注 → 其他字段 → 固定底部保存按钮；只呈现实体已有字段（C28） |
| 沉浸选择 | 选境、比较选择 | 问题与进度 → 选项分区 → 返回/重来 → 更多说明 |

每个新页面必须先选模板，再安排内容。不要为普通表单或列表另创一种导航布局。文章阅读、账号认证等特殊用途可以另立模板并说明使用场景。

## 3. 首屏内容分配

| 功能 | 核心区 | 次级区域 |
| --- | --- | --- |
| 番茄钟 | 时钟、事项、开始/暂停、结束/重置、今天的投入 | 分析、历史、节奏、提醒 |
| 任务 | 四象限、完成状态、时间排序、筛选入口、创建入口 | 数据分析、同步状态 |
| 习惯 | 今日概览、按领域筛选的习惯网格、待打卡推荐、创建入口 | 全部习惯、日历、管理 |
| 选境 | 当前问题、进度、对齐选项、返回与重来 | 选项详细解释、历史回看 |

筛选打开在当前页的明确面板中，显示当前条件、匹配数量、清除按钮和查看结果按钮。不要把“筛选”伪装成跳到不相关页面底部的链接。

## 4. 共用设计变量（Design Tokens）

设计变量是给颜色、间距、字号等决定起固定名字，例如 `space.section`、`color.text.secondary`。页面引用名称，避免分别写一套近似值。小程序和网页可输出不同的单位，共用同一套语义。

以下为建议基线，以逻辑像素描述，不等于在所有设备上把同一个 rpx 值机械放大：

| 属性 | 允许的基础值/规则 |
| --- | --- |
| 间距 | 4、8、12、16、24、32；组件内部常用 8/12，分组常用 24 |
| 页面边距 | 手机一般 16；高密度四象限允许 8，作为模板例外 |
| 圆角 | 控件 8，卡片 12，弹层 16；胶囊仅用于标签/状态 |
| 字号 | 注释 12，次要内容 14，正文/输入 16；内容分组小标题按 [C67](../Design.md#通用小标题c67) 为固定 14px／600，页标题与翻页分区主标题保持各自层级；计时数字单列特殊字号 |
| 字重 | 正文 400，强调 600；不要以大量粗体代替层级 |
| 行高 | 正文约 1.5，标题约 1.3；按钮必须垂直居中 |
| 图标画布 | 通常 20/24，大图标 32/48；统一光学大小和描边 |
| 触控区域 | 适配后至少 44×44 逻辑像素；小图标可通过透明内边距扩大点击区域 |
| 动效 | 约 160–240 ms；只解释状态或位置改变，不妨碍连续操作 |

颜色分为背景、表面、主文字、次文字、边框、主操作、成功、警告、错误。番茄红、习惯叶绿、四象限颜色属于功能主题，不能改写“禁用”“选中”“错误”的交互含义。不要只靠颜色传达状态。

可使用 DTCG 格式维护跨工具的变量。该规范描述共享颜色、尺寸等设计决定的命名和值，属于社区规范，并非完整的页面设计系统：[Design Tokens Format Module 2025.10](https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/)。以上具体数值是 Ottlog 的建议值，不是该规范规定的尺寸。

## 5. 组件契约

- **主要按钮**：明确底色、完整点击区域、动词文案；同一操作组只有一个视觉上最强的按钮。
- **次要按钮**：边框或较弱底色；“重置”“调整节奏”等可执行操作不得只剩没有点击感的普通文字。
- **文字链接**：用于低优先级导航；不要承担保存、完成、危险删除等主要操作。
- **输入表单**：按 C28 安排日程、标题图标和优先度，备注在标题下直接显示；输入提示不能代替字段语义和必要校验。
- **标签**：同样的高度、内边距、选中状态；常用项排成一行，末端展开悬浮多选窗，前排与浮窗共享选择。
- **选择及展开按钮**：小程序普通单选由一个图标／文字按钮打开悬浮小选项窗；可自定义选择项常用在前、创建默认最常用、末尾提供自定义输入，编辑保留原值。共用 `SelectTrigger` 的状态样式和 `SelectChevron` 的上下 chevron；打开顺时针旋转 180°，关闭逆时针旋转 180°。系统交互例外见 C12。
- **图标**：来源固定、大小统一；小程序使用已验证资源，禁止用可能被系统渲染成 emoji 的字符充当产品图标。
- **展开控件**：稳定文字与几何尺寸，统一 C28 旋转上下 chevron，并提供展开状态；多标签的展开按钮位于常用行末端。
- **拖动**：可识别把手或明确长按提示，拖动影子、有效目标、插入位置反馈；取消不保存，完成不误触编辑，连续拖动不能跳回旧位置。
- **统计图**：次数/时长随日期用柱状图，分类比较用条形图；数据点可查看数值和明细；期间、单位、口径及无数据状态明确显示。

所有交互组件都需要定义：默认、按下、选中、禁用、加载、失败。未定义状态的组件不能只凭默认截图验收。

## 6. 布局与适配规则

- 同一层级卡片共享边缘、间距、内容起点。先建立列和行，再添加装饰图形。
- 常用标签与末端展开按钮按 [C30](../Design.md#标签行与展开间距c30) 紧邻排列；少量内容不填满剩余宽度，空文本不占位，长文本在自己的节点内省略并保留完整选择入口。
- 装饰不改变文字阅读顺序和点击区域。异形选境用共享坐标计算背景与命中，不能出现“看到 A，点到 B”。
- 采用内容约束的弹性布局。页面级样式只安排结构，通用按钮、表单、标签从公共组件继承。
- 弹层按钮栏沿用 [C29](../Design.md#弹层底部操作c29) 与共享 `SheetActions`，避免原生导航已处理的安全区再次叠加；同一边界只保留一条分隔线，不能由相邻区块各画一条。
- 默认视图按 [C32](../Design.md#默认视图完整性c32) 完整显示关键模块和控件，扣除实际导航、固定操作栏与必要安全区；日历等核心模块不能露出半截或被按钮遮挡。习惯详情尺寸随可用视口限制，长标题默认最多两行并明确展开全文，长备注提供同类阅读入口，完整原文保留；编辑器备注仍常显。长列表和历史使用明确可滚动区域，保留可读字号及至少 40px 触控，联合检查长标题／长备注／专注入口，不以裁切或过度压缩换取首屏完整。
- 禁止通过一个公共 CSS 文件不断叠加页面特定覆盖来补救局部错位。修正应归到所属模板或组件，并清理失效规则。
- 网页宽屏设置内容最大宽度或增加列数，不把手机界面整体等比例放大；小程序考虑胶囊、导航栏、底部安全区和键盘。
- 只有需要独立处理大量内容的区域才使用嵌套滚动，如四象限各自的任务列表。其他页面优先使用一个主滚动容器。
- 小程序适用的工具页复用 `PageScroll`、`CoreScreen`、`MoreSection`。核心页占一个可用视口，更多内容按实际长度自然增长；保留首页 C20 三段和领域导航等已实现例外，不另造重复滚动吸附。`test:screens` 检查适用页面的首屏高度和内容溢出，`test:page-snap` 检查往返对齐与长页自由滚动。
- 名称、空状态、长文字、多标签、大数字、打开键盘都需要实际检查，不能只看空白初始页。

## 7. 修改流程与验收

每次 UI 修改都附上这六项，作为任务说明与检查依据：

1. **用户任务**：用户进入后首先要完成什么？
2. **模板**：采用上述哪类结构？哪些部分复用？
3. **变更边界**：只改文案、样式、布局，还是交互/数据？
4. **状态**：空、已有数据、加载、错误、编辑、进行中如何表现？
5. **截图**：至少手机窄屏、短屏与宽屏；重要修改覆盖 iPhone 真机。
6. **验证**：点击/触摸和持久化验证；编译包的页面注册检查与浏览器预览分开。

建议的预览尺寸为 360×844、375×667、430×844、768×1024；网页额外检查桌面宽度。尺寸检查不能替代字体放大、安全区、键盘及微信真机验证。

如果内容放不下，处理顺序固定为：简化内容 → 移次要内容到次级区域 → 调整模板列数 → 允许滚动。缩小到难读难点的字体和按钮不是验收合格的办法。

## 8. 怎样成为实际约束

建议持续维护三层资产：

- 本文件：页面模板、组件语义、允许的例外、验收方式。
- 公共变量与组件：让规范直接进入代码，减少临时 CSS 数值。
- 固定样例与回归截图：创建表单、工作区、推荐页、选境各保留一组参考状态。

后续可在仓库的 `AGENTS.md` 或任务模板中加入：“修改 UI 前阅读 docs/design-system.md；先复用模板和组件；新增例外要注明原因；报告截图和运行环境。”本次先建立指南，不代表已经将全站代码迁移到新的变量与组件体系。
